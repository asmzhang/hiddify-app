### 屏3 设置页 —— 78%

五类内联结构（基础 / 路由 / DNS / 入站 / 其他）已实装（`settings_page.dart:140-376`），行样式统一走 `nk_setting_rows.dart`（NkSwitchRow/NkValueRow/NkChoiceRow/NkNavRow）。

**三处内容缺陷：**

1. **第五类标题写错** —— `settings_page.dart:321` 用的是 `t.pages.settings.options.reset`，该键值是 **"Reset options"**（`en.i18n.json:229`），不是"其他"。页面上会显示成"重置选项"。
2. **同一能力出现两个入口** —— `strictRoute`（严格路由）同时出现在「路由」卡（`:240`）和「入站」卡（`:306`），违反项目自己的"归一原则"。
3. **MTU 是无入口的孤儿配置** —— `config_option_repository.dart:141` 定义了 `mtu`（默认 9000，mockup 屏3 明列此项），但没有任何 UI 引用，只能进 JSON 编辑器改。

**没有对应后端的 mockup 项（非实现疏漏，属能力缺口）：**

| mockup 项 | 实际情况 |
|---|---|
| 流量嗅探 | hiddify 侧无 sniffing 配置项（全库无 `sniff` 相关 option） |
| 网络切换时重置连接 | 无对应选项 |
| 绕过局域网地址 | 存在，但形态是「路由 → 预设规则 → Bypass LAN」（`predefined_rules_modal.dart:83`），不是设置页开关 |

其余项已对齐：自动连接（桌面 autoStart）/ 主题色 / 夜间模式 / 服务模式 / 日志级别 / 地区 / IPv6 / 严格路由 / 负载均衡策略 / 远程·直连 DNS + domain_strategy / FakeDNS / 混合端口 / 允许局域网 / 延迟测试 URL / Clash API + 端口 / xray-core。

### 屏4 节点编辑页 —— 45%

已有：Toolbar（← 标题 ✓保存）+ 名称 / 订阅 URL / 自动更新 / 流量四张 NkCard + JSON 配置编辑器（`profile_details_page.dart`）。

**缺的正是 mockup 的主体**：协议级字段表单 —— 地址 / 端口 / UUID / alterId / 加密 / 传输网络 / 伪装 host·path / TLS（SNI、ALPN、允许不安全）/ Mux（协议、并发数）。当前这些字段只能通过 JSON 编辑器改。

## 3. 死代码 / 一致性隐患（逻辑层面）

1. **4 个 NekoBox 组件零引用**：`connection_dashboard.dart`、`traffic_speed_bar.dart`、`ping_badge.dart`、`protocol_chip.dart` —— 复刻期造好但从未接线。其中 `protocol_chip` 尤其讽刺：节点卡正需要它，实装却手写了同逻辑的彩色文字（`proxy_tile.dart:125-128` 与 `ping_badge` 文案规则重复）。
2. **仪表盘 ↑↓ 配色与 StatsBar 不一致**：仪表盘用 `Colors.green`/`colorScheme.error`（`stats_overview_page.dart:49-54`），StatsBar 用 `onPrimary` 白字。
3. **节点卡的 ping 文案规则被复制两份**（`proxy_tile.dart:45-51` 与 `ping_badge.dart`）。
4. `settings_page.dart:321` 与 `tools_page.dart:150` 都把 `options.reset` 当节标题用 —— 工具页那里语义正确（重置），设置页那里是误用。

## 5. 审计结论

- **视觉壳**：达标。主色 Toolbar + 分组 Tab + 三行卡 + 主色 StatsBar + FAB 四态 + 五类设置 + 三组抽屉 + PC Rail，与 mockup 的结构一一对应。
- **交互一致性**：基本达标（归一原则大体遵守，但 `strictRoute` 双入口是反例）。
- **功能完整性**：**未达标**。屏4 是空壳（45%），节点卡动作缺失，3 处设置内容缺陷。
- **可维护性**：⚠️ 有 4 个未接线的组件与 1 处逻辑重复，属复刻期的"半成品遗留"。

判定：**UI 布局"形式上达标、实质上有缺口"** —— 当"外观验收"通过，当"功能对齐验收"不通过。建议先清 P0+P1（都是小改），P2 随实体级那一批一起做。
